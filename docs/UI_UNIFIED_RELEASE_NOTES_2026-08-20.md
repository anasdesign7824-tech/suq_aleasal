# تقرير ترقية الواجهة الموحدة — عسلكم

## نطاق الإصدار

يهدف هذا الإصدار إلى توحيد تجربة عرض الملف الشخصي والمتجر والمنتج والمراسلات والإشعارات بين العميل والتاجر والإدارة، مع إبقاء الصلاحيات مختلفة حسب الدور. لم تُنشأ واجهة بديلة أو مسار تجريبي جديد؛ جرى توسيع المكونات المشتركة الحالية وربط الأزرار بمسارات المستودع الفعلية.

> القاعدة المعتمدة: **قالب عرض واحد + نموذج بيانات مشترك + صلاحيات مختلفة حسب الدور**.

## ما تم تطبيقه

| المجال | التطبيق |
|---|---|
| الملف الشخصي | استبدال رأس الملف الخاص بالعميل ببطاقة `AssalProfileHeaderCard` المشتركة، مع الغلاف والصورة والاسم والبريد والهاتف والموقع والنبذة وشارة الدور ومسار التعديل الحقيقي. |
| المتجر | توحيد رأس المتجر بين واجهة العميل ولوحة التاجر عبر `AssalStoreHeaderCard`، مع إبقاء أدوات التحديث والتحرير للتاجر فقط. |
| المنتجات | استخدام `ProductCard` المشترك للعميل والتاجر، مع إظهار التحرير والحذف للتاجر فقط. |
| رفع الصور | جعل موضع الصورة نفسه قابلًا للنقر عبر `AssalImageTile` و`AssalImageUploadGrid`، مع الإضافة والاستبدال والحذف والمعاينة داخل البلاطة بدل زر خارجي منفصل. شمل ذلك الملف الشخصي والمتجر والمنتج. |
| المحفوظات والمتابعات | تثبيت ارتفاع شريط التبويبات، فصل التبويبين بوضوح، وإعادة استخدام بطاقة المنتج والمتجر المشتركة مع إجراء إزالة المتابعة الحقيقي. |
| الإشعارات | إضافة `AssalNotificationCard` مع حالة جديد ومعالجة صور الإشعار المعطوبة وإظهار نتيجة تعليم الإشعار كمقروء. |
| المراسلات | إضافة `AssalConversationCard` و`AssalMessageBubble` لتوحيد قائمة المحادثات وفقاعات الرسائل مع إعادة تحميل حقيقية بعد الإرسال. |
| الدعم والمساعدة | إضافة `SupportCenterScreen` بأسئلة شائعة ومسار دعم فني عربي عبر بريد الدعم الرسمي. |
| طلب التصميم | إضافة `DesignRequestScreen` مرتبط بـ `createDesignRequest`، يتحقق من الجلسة والخطة ويرسل العنوان والتفاصيل واسم العلامة والألوان إلى المستودع الحقيقي. |
| المزايا المدفوعة | إظهار `AssalPremiumBadge` داخل بطاقات الخطط المدفوعة، وإظهار `InfoChip` للتوثيق وطلبات التصميم، مع قفل طلب التصميم عند عدم وجود استحقاق. |
| لوحة الإدارة | إضافة `AdminSafeImage` لمعالجة الصور المعطوبة، واستخدامها في البنرات وطلبات التجار والمستخدمين وتفاصيل التوثيق، وإضافة `AdminPremiumBadge` إلى بطاقات الخطط وشارة توثيق Pro. |

## المزامنة والصلاحيات

لم يتم تجاوز طبقة المستودع أو إنشاء نجاح وهمي. عملية طلب التصميم تستعمل عقد `AssalRepository.createDesignRequest`، وعمليات الإشعارات والمراسلات تستعمل العقود القائمة مع إظهار حالات الخطأ العربية. القالب مشترك بصريًا، بينما تبقى عمليات العميل للعرض والتفاعل، وعمليات التاجر للتحرير والإدارة، وعمليات الإدارة للمراجعة والاعتماد والحذف، وفق الصلاحيات الحالية.
