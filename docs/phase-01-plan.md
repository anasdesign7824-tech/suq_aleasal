# Phase 1 — تأسيس المشروع والحوكمة

## السلطة والنطاق

هذه الوثيقة تفسر الخطة التنفيذية المعتمدة ولا تستبدلها. المرجع الأعلى هو `pasted_content_2.txt`، مع اعتماد الوثيقة التنفيذية الأصلية وملف `pasted_content.txt` وجميع الأصول المرجعية حسب أدوارها المحددة. الاسم الهندسي الداخلي الثابت هو **Souq Al Assal / سوق العسل**، والاسم التجاري الظاهر هو **عسلكم**.

Phase 1 مخصصة لتأسيس مشروع Greenfield والحوكمة فقط. لا تشمل بناء ميزات المنتج، ولا تحليلًا تفصيليًا للأصول، ولا تصميمًا نهائيًا لقاعدة البيانات، ولا تنفيذ Supabase، ولا إنشاء UX للمستخدم أو التاجر أو الإدارة، ولا الانتقال إلى Phase 2 قبل اجتياز بوابة القبول.

## أهداف المرحلة

تتمثل أهداف المرحلة في تثبيت هوية المشروع وأسمائه، إنشاء حدود المستودع وبنيته الأولية من الصفر، توثيق المخرجات الثلاثة، تثبيت قواعد Demo-First وRepository Abstraction والفصل بين UI وDomain وData Sources، توثيق قاعدة Supabase كمصدر إنتاج رسمي دون جعله شرطًا لـ Demo Mode، وتسجيل جميع الملفات المرجعية وأدوارها دون خلط بينها.

## القيود غير القابلة للتغيير

لا يجوز في هذه المرحلة أو بعدها تغيير Product Vision، أو طبيعة المنصة الاجتماعية/التجارية، أو Flutter/Dart، أو العربية وRTL، أو Demo-First، أو Repository Abstraction، أو Design System Contract، أو تجربة العميل والتاجر، أو Admin Architecture، أو Security Model وRLS، أو فصل الطبقات، أو فصل Demo عن Production، أو ترتيب المراحل وبوابات القبول.

أي تعارض تقني يمس ثابتًا يُسجل بالترتيب: `CONFLICT → ROOT CAUSE → IMPACT → OPTIONS → RECOMMENDATION → USER DECISION IF REQUIRED`. لا يُحل بالتخمين ولا يُستخدم لتغيير المفهوم.

## بوابة Phase 1

لا تُقبل المرحلة إلا بعد اكتمال التسلسل التالي: **PLAN → IMPLEMENT → RUN → VERIFY → TEST → VISUAL CHECK → ARCHITECTURE CHECK → FIX → RETEST → EVIDENCE → GIT COMMIT → ACCEPTANCE GATE**.

### معايير القبول

1. وجود بنية مستودع موثقة باسم هندسي `Souq Al Assal` دون كود أو قالب سابق.
2. وجود وثائق واضحة تفرق بين الاسم الهندسي الداخلي `Souq Al Assal` والاسم التجاري `عسلكم`.
3. وجود سجل مرجعي لكل ملف مرفق يحدد دوره ويمنع استخدام الصورة الفلسفية أو الصورة المرجعية كمصدر معماري.
4. وجود وثيقة معمارية أولية تثبت Flutter/Dart وDemo-First وRepository Abstraction وفصل UI/Domain/Data.
5. وجود وثيقة تكامل تنص صراحة على أن Supabase مصدر الإنتاج الرسمي وليس شرط تشغيل Demo Mode، وأن العقود Dart للموبايل وTypeScript للويب عند الحاجة.
6. عدم وجود أسرار أو مفاتيح أو ملفات بيئية حقيقية في المستودع.
7. نجاح فحوص المستودع والوثائق، وعدم وجود مسارات أو أسماء مخالفة للعقد التجاري/الهندسي.
8. إنشاء commit موثق خاص بالمرحلة مع تقرير Evidence يتضمن الملفات والاختبارات والملاحظات وحالة القبول.

## الأدلة المطلوبة

يجب أن يتضمن تقرير المرحلة: `Phase`, `Implemented`, `Files`, `Tests`, `Build`, `Visual verification`, `Architecture verification`, `Known issues`, `Fixes`, `Acceptance status`, و`Git commit`. نجاح البناء أو إنشاء الملفات وحده ليس دليلًا على القبول.

## نتيجة المرحلة المتوقعة

عند القبول، يصبح المستودع مهيأً للانتقال إلى Phase 2 — تحليل الأصول والبيانات — دون تنفيذها ضمن هذه المرحلة. عند الفشل، تبقى المرحلة الحالية ولا يُسمح بالانتقال.
