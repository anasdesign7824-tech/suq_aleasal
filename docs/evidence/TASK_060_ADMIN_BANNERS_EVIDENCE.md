# دليل TASK 060 — البنرات الحية في لوحة الإدارة

**التاريخ:** 23 أغسطس 2026

**النطاق:** مراجعة إنشاء البنرات ورفع صورها وجدولتها ونشرها وإيقافها وحذفها، مع إبقاء عمليات الكتابة عبر API والعقود القائمة.

## ملاحظة المصدر

فهرس ما قبل التغيير يربط TASK 060 بـ`AdminOperations.tsx` و`admin-api.ts` و`admin-data.ts` ويصف مرجعًا مكتبيًا 1600×1000. ملفا `screens/060_admin_banners.png` و`explanations/060_admin_banners.md` غير موجودين في checkout الحالي أو شجرة GitHub المتاحة، لذلك لم تُنشأ صورة أو golden بديل.

## الجرد والتنفيذ

يقرأ `BannersPanel` البنرات من `adminApi.banners` ويعرض حالات loading/error/empty/retry، ويتيح إنشاء مسودة بعنوان ووصف وصورة ورابط CTA وترتيب وجدولة، مع تحقق من ترتيب التواريخ، ورفع محلي إلى Storage عبر `uploadPublicImage` ومعاينة آمنة. يحدد `scheduleLabel` الفرق بين مسودة/متوقف ومجدول ومنشور ومنتهٍ. يمر النشر والإيقاف والحذف عبر `updateBanner/deleteBanner` الحقيقيين، والحذف يحظى بتأكيد.

كُشف أن النشر والإيقاف والحذف لا يملكان حارسًا لكل بانر، وأن النشر عالي الأثر بلا تأكيد، كما أن قبول `accept` في حقل الملف لا يغني عن تحقق MIME. عولج ذلك بإضافة `bannerBusyId` وتعطيل أفعال البانر أثناء الطلب، وتأكيد عربي للنشر والإيقاف، والتحقق الصريح من PNG/JPEG/WebP قبل قراءة الملف. لم يتغير عقد الجدولة أو API أو DB/RLS/الصلاحيات.

## بوابات الإثبات

| البوابة | النتيجة |

| `pnpm test` | PASS — 8 ملفات اختبار قائمة |

| `pnpm build` | PASS — Vite وesbuild؛ تحذير chunk أكبر من 500 kB بقي تحذير أداء |
| مراجعة banner path | PASS — list/error/retry، draft، upload/preview، schedule validation، publish/stop/delete confirmation، busy guard، safe image fallback |

النتيجة المهيكلة محفوظة في `artifacts/task060_admin_banners_result.json`.

## الحدود والقرار

لم يُنشأ أو يُنشر أو يُحذف بانر Production حي خلال المهمة، ولم تُشغّل مقارنة golden لغياب Markdown وPNG. لا يُدّعى ظهور البانر على تطبيق العميل أو مزامنة حية؛ ذلك يحتاج عملية كتابة واعتماد آمن واختبارًا منفصلًا عبر المستهلك الحقيقي.

**قرار TASK 060:** PASS للتعديل الوظيفي المحدود والبناء والاختبارات، مع GAP-034 لفقدان أصول التدقيق البصرية/السلوكية. لا تغيير DB/API/RLS/الصلاحيات.
