# تقرير تنفيذ إعادة بناء واجهة عسلكم — 2026-08-17

## نطاق التنفيذ

تم تنفيذ الجولة المرئية والوظيفية في المصدر المشترك لتطبيق عسلكم، بحيث تنعكس على Demo وProduction وDebug وRelease وجميع بنيات ABI. لم تتم إضافة بيانات وهمية إلى Production، ولم يُغلق عقد البانرات؛ بل جرى تحسين طريقة عرضه مع إبقاء استقبال الصور من `customer_banners` جاهزًا لتكامل لوحة التحكم لاحقًا.

## التغييرات المنفذة

| المجال | التنفيذ |
|---|---|
| System Chrome | توحيد لون status bar وnavigation bar مع اللون البني الداكن، وإبقاء الأيقونات فاتحة. |
| Toolbar | ربط الشاشات بالمكون المشترك `AssalAppBar` مع التدرج الداكن، شعار عسلكم، الرجوع الحقيقي، و`TabBar` عند الحاجة. فحص المصدر لم يُظهر `appBar: AppBar` خامًا في شاشات التطبيق. |
| Home Header | تحويل الرأس إلى مساحة ثابتة مضغوطة بتدرج عسلكم، شعار وإشعارات وإعدادات، ticker زجاجي متحرك، وحقل بحث واضح. أزيلت البطاقة الكبيرة الثابتة التي كانت تستهلك مساحة الشاشة. |
| حالات التحميل | إعادة تبسيط `AssalGlassLoading` إلى حالة مباشرة بأيقونة خلية متحركة ونص، دون حاوية كبيرة أو skeleton يسبب overflow. |
| Production banners | عند خلو البيانات الحقيقية أو عدم وجود صورة صالحة يختفي slot بدل عرض Hero أو حملة Demo. في Demo فقط يبقى fallback التجريبي. عند وصول `image_url` من لوحة التحكم تُعرض الصورة داخل carousel قابل للنقر. |
| الصور | دعم `http` و`assets/` في بطاقة البانر، مع fallback خفيف للصورة غير الصالحة. |
| الشعار الداخلي والخارجي | إضافة `nameColor` إلى `AssalBrandMark`، وإدخال الشعار الخارجي المضغوط إلى Flutter assets، مع إبقاء ملفات المصدر الضخمة خارج runtime. |
| OTP وDemo-first | الحفاظ على إصلاح قبول الرمز الرقمي، وإعادة import محمل Demo حتى يعمل التطبيق بلا Supabase. |

## ضغط الشعارات

تمت معالجة جميع PNG المضمنة داخل ملفات runtime فقط بضغط PNG lossless وتحجيم الصور ذات الدقة العملاقة إلى حد عملي 1024px. لم يُستخدم توليد جديد للشعار، حتى لا تتغير الهوية أو التفاصيل.

| الأصل | قبل | بعد | الملاحظة |
|---|---:|---:|---|
| `logo-internal-runtime.svg` | 426,517 bytes | 426,517 bytes | أبقي كما هو لأن إعادة الضغط لم تنتج ملفًا أصغر. |
| `logo-external-runtime.svg` | 7,937,162 bytes | 603,110 bytes | خفض كبير مع الحفاظ على الشفافية ودقة مناسبة لاستخدامات التطبيق. |

## عقد البانرات المستقبلي

يبقى `AssalBannerSummary` مستقبلاً للحقول `id` و`title_ar` و`description_ar` و`cta_label_ar` و`image_url` و`target_query` و`sort_order` و`is_active`. لا يحتاج بناء لوحة التحكم القادم إلى تغيير في عقد التطبيق؛ يكفي رفع الصورة وتخزين الرابط في `customer_banners` مع بقية الحقول.

## الفحوص والبناء

نجح `flutter analyze --no-pub` دون أخطاء، ونجحت الاختبارات كاملة بعد تحديث assertion الخاص بالنص التعريفي ليتوافق مع ticker الجديد: **11 اختبارًا ناجحًا**.

| النسخة | ABI | الحجم |
|---|---|---:|
| Demo Release | armeabi-v7a | 18,875,258 bytes |
| Demo Release | arm64-v8a | 21,282,408 bytes |
| Demo Release | x86_64 | 22,756,615 bytes |

## حدود التحقق

لم يكتمل التحقق التفاعلي الأخير على Mimo لأن `adb devices` أعاد قائمة فارغة بعد البناء. لذلك لا أصف التحقق البصري على الجهاز بأنه مكتمل. الكود اجتاز التحليل والاختبارات والبناء، لكن تثبيت APK النهائي وتصوير Home وSearch وStores وFilterSheet وLogin يحتاجان اتصال Mimo من جديد. لا توجد حاليًا بيانات في جداول Production الخاصة بالمتاجر والمنتجات والبانرات، ولذلك ظهور حالات الفراغ في Production متوقع وصحيح.
