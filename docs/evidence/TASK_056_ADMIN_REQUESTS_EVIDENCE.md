# دليل TASK 056 — طلبات التواصل وتفاصيلها في Admin

**التاريخ:** 23 أغسطس 2026

**النطاق:** مراجعة قائمة طلبات التواصل وSheet التفاصيل ومسار الرد الإداري، مع إبقاء الحفظ عبر API والعقد القائمين.

## ملاحظة المصدر

فهرس ما قبل التغيير يربط TASK 056 بـ`Home.tsx` و`admin-api.ts` و`admin-data.ts` ويصف مرجعًا مكتبيًا 1600×1000. ملفا `screens/056_admin_requests.png` و`explanations/056_admin_requests.md` غير موجودين في checkout الحالي أو شجرة GitHub المتاحة، لذلك لم تُنشأ صورة أو golden بديل.

## الجرد والتنفيذ

تستخدم القائمة `adminApi.requests` مع حالات loading/error/empty وتحديث حقيقي، وتفتح الطلب المحدد في Sheet يعرض الموضوع والوصف والحالة ونموذج «إرسال رد حقيقي». يستدعي النموذج `adminApi.answerRequest`، ويحدّث المصدر بعد النجاح، ويعرض خطأ دون إخفاء السياق عند الفشل. كان الزر قابلًا لإرسال متكرر أثناء انتظار الشبكة؛ عولج ذلك داخل `Home.tsx` بإضافة `replying`، وحماية submit، وتعطيل الزر عند الفراغ أو الإرسال، مع نص «جارٍ إرسال الرد…» أثناء الطلب.

في الخادم، يتحقق `answerRequest` من وجود جلسة وصلاحية إدارة، ويُدخل رسالة في `request_messages`، ويحدّث حالة الطلب إلى `answered`، ثم يسجل `request.answer`. لم تُضف قناة مراسلة جديدة أو إشعارًا وهميًا، ولم تُنفذ كتابة Production في هذه المهمة.

## الحدود والقرار

لم تُرسل رسالة حقيقية إلى Production، ولم تُشغّل مقارنة golden لغياب Markdown وPNG. لا يُدّعى وصول الرد إلى هاتف أو مزامنة لحظية؛ ذلك يحتاج جلسة وحسابات اختبار معتمدة وقابلة لإعادة الإنتاج.

**قرار TASK 056:** PASS للتعديل الوظيفي المحدود والبناء والاختبارات، مع GAP-030 لفقدان أصول التدقيق البصرية/السلوكية. لا تغيير DB/API/RLS/الصلاحيات.
