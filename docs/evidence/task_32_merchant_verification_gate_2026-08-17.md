# Task 32 — توثيق التاجر

## النطاق

إظهار حالات التوثيق في شاشة «كن تاجرًا» دون تنفيذ رفع مستندات حقيقية أو اختلاق انتقالات حالة غير موجودة.

## التنفيذ

أضيفت بطاقة «حالة التوثيق» في `BecomeMerchantScreen` وتعرض الحالات التالية بحسب قيمة الحالة التي يعيدها Repository:

| القيمة | العرض العربي |
|---|---|
| لا توجد حالة | لم يبدأ بعد |
| `submitted` | تم الإرسال |
| `under_review` | قيد المراجعة |
| `verified` | موثق |
| `rejected` | مرفوض — يحتاج إلى تعديل |

توجد أوصاف عربية لكل حالة. الحالة الافتراضية «لم يبدأ بعد» لا تعني نجاحًا ولا توثيقًا؛ هي الحالة قبل إرسال الطلب. كما أضيفت قراءة `loadMerchantApplication` إلى العقد، ويعيد Demo الحالة الفعلية الموجودة في الذاكرة، بينما يعيد Production حالة `production_merchant_application_not_configured` صريحة بدل إنشاء حالة مزيفة.

لا يوجد زر رفع مستندات ولا استدعاء Storage. تظهر رسالة واضحة بأن الرفع الحقيقي مؤجل إلى حين تهيئة التخزين والمراجعة الإدارية، مع إبقاء حقل معلومات المصدر/الشهادات النصي الاختياري.

## الحدود المعمارية

الشاشة تعتمد على `AssalRepository` فقط. لا توجد Supabase calls داخل Widget، ولا fake success في Production، ولا انتقالات تلقائية من `submitted` إلى `under_review` أو `verified` من داخل التطبيق.
