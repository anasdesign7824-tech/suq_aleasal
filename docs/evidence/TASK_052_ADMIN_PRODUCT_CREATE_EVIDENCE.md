# دليل TASK 052 — إنشاء منتج في لوحة الإدارة

**التاريخ:** 23 أغسطس 2026

**النطاق:** مراجعة مسار إنشاء المنتج الإداري من النموذج إلى API المحلي وخدمة البيانات، دون تنفيذ كتابة في Production ودون تغيير DB/API/RLS/الصلاحيات.

## ملاحظة المصدر

فهرس ما قبل التغيير يربط TASK 052 بـ`ProductCreationPanel.tsx` و`admin-api.ts` ويصف مرجعًا مكتبيًا 1600×1000. ملفا `screens/052_admin_product_create.png` و`explanations/052_admin_product_create.md` غير موجودين في checkout الحالي أو شجرة GitHub المتاحة، لذلك لم تُنشأ صورة أو golden بديل.

## الجرد المصدرّي

يبدأ النموذج باختيار متجر وتصنيف واسم عربي، ثم يتيح الاسم الإنجليزي والوصف والنوع ودرجة الجودة والسعر والعملة والوزن وبلد المصدر والمحافظة/المديرية وبيانات الجودة والحصاد والتغليف والتواريخ والصلاحية والتوفر والتوصيل والاستلام والمكونات والوسوم والشهادات والصور. القوائم المرجعية تأتي من `adminApi.taxonomy()` و`adminApi.regions()`، ويُحوّل `textMetadata` القيم النصية والقوائم إلى `metadata` منظم، بينما يمر رفع الصور عبر `adminApi.uploadPublicImage` بعد التحقق من النوع والحجم.

عند الحفظ يرفض النموذج المتجر أو التصنيف أو الاسم العربي المفقود والسعر غير الصالح، ثم يستدعي `adminApi.createProduct` بحالة `draft` ومسار الخادم `createProduct`. يتحقق الخادم من `product.write`، ويبني صف المنتج، ويسجل الصور في `product_images` وسجل التدقيق وفق العقود الموجودة؛ لا توجد دالة UI مباشرة إلى Supabase. عولجت حالات فشل المراجع في TASK 051، وبقيت هنا موثقة ومتصلة بنفس retry/source boundary دون تعديل إضافي.
