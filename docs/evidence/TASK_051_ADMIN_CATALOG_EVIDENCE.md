# دليل TASK 051 — إدارة كتالوج Admin

**التاريخ:** 23 أغسطس 2026

**النطاق:** تدقيق قائمة الكتالوج ومحرري إنشاء/تعديل المنتج في لوحة الإدارة المحلية، مع الإبقاء على مسارات المصدر الفعلية وعدم إضافة DB/API/RLS/صلاحيات.

## ملاحظة المصدر

فهرس ما قبل التغيير يربط TASK 051 بـ`Home.tsx` و`ProductCreationPanel.tsx` و`ProductEditPanel.tsx` و`admin-api.ts`، ويصف مرجعًا مكتبيًا بأبعاد 1600×1000. ملفا `screens/051_admin_catalog.png` و`explanations/051_admin_catalog.md` غير موجودين في checkout الحالي ولم يظهر مسارهما في شجرة GitHub المتاحة؛ لذلك لم تُنشأ صورة أو golden بديل.

## الجرد والتنفيذ

تستخدم قائمة الكتالوج `ProductTable` مصدر `adminApi.products` مع حالات التحميل والخطأ والفراغ وإعادة التحديث، وبحث محلي، وتفاصيل وتعديل وحذف عبر callbacks حقيقية. يستخدم `ProductCreationPanel` مسارات `adminApi.taxonomy` و`adminApi.regions` و`adminApi.uploadPublicImage` و`adminApi.createProduct`، بينما يستخدم `ProductEditPanel` مسارات التصنيف والرفع و`adminApi.updateProduct`. الحقول الحالية تشمل المتجر والتصنيف والهوية والوصف والنوع ودرجة الجودة والسعر والعملة والصور والبيانات الوصفية والتوفر والتوصيل والاستلام، ولم تُضف حقولًا خارج العقد القائم.

كانت أخطاء قراءة مراجع الإنشاء والتعديل تُرسل إلى toast فقط، ما يترك المستخدم أمام اختيارات معطلة أو غير واضحة وإجراء حفظ بلا تفسير. عولج ذلك بشكل محدود: يحتفظ الإنشاء بـ`referenceError` ويعرض تنبيهًا عربيًا وزر «إعادة المحاولة» يعيد طلب `taxonomy/regions`، ويعطل اختيارات المراجع عند الفشل؛ ويحتفظ التعديل بـ`taxonomyError` وزر retry ويعطل اختيار التصنيف حتى عودة المصدر. بقي رفع الصور والتحقق من النوع والحجم والحفظ كمسودات أو تحديث المنتج موصولًا بالعقود الأصلية، وبقيت إزالة الصور في المحرر تعديلًا حقيقيًا عبر `imageUrls` عند الحفظ، لا نجاحًا شكليًا.
