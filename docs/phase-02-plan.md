# Phase 2 — تحليل الأصول المرجعية وبيانات العسل

## النطاق

تُحلل هذه المرحلة الأصول التي اعتمدها المستخدم بحسب أدوارها المحددة، وتُراجع بنية ملف بيانات العسل، وتُنتج سجل قرارات قابلًا للتتبع. لا تُبنى واجهات أو قاعدة بيانات إنتاجية في هذه المرحلة، ولا تُستخرج هوية جديدة من الصورة الفلسفية، ولا يُعاد تفسير المرجع البصري باعتباره معمارية.

## المسار المعتمد لكل ملف

| المصدر | المخرج المطلوب |
|---|---|
| Prompt التنفيذي وملفات السلطة | مصفوفة ثوابت ونطاق تنفيذي |
| حزمة صور هوية التطبيق | ملاحظات أسلوبية ومرجعية للتكوين والبطاقات والألوان، دون نسخ معمارية |
| حزمة الشعار والأيقونات | سجل أصول وأدوار استخدام للتطبيق وSplash وLanding وfavicon |
| ملف IBM Plex Sans Arabic | سجل أوزان الخط وخطة إدخاله في Design System |
| Honey Master JSON | تقرير بنية، تحقق من المعرفات والتكرارات والحقول، ومسودة seed دلالية لاحقة |
| الصورة الفلسفية للشعار | سجل أنها مرجع فهم فقط، دون استخراج قرارات تصميمية ملزمة |

## خطة التحليل

سيتم أولًا فحص الأرشيفات وقوائم الملفات دون تشغيل مرفقات غير موثوقة، ثم تحليل JSON برمجيًا لاستخراج عدد الأقسام والتصنيفات والمنتجات والمعرفات والحقول والقيم غير المتجانسة. بعد ذلك تُثبت الألوان واللغة البصرية الظاهرة في المرجع المقدم، وتُسجل الأوزان المتاحة للخط، وتُراجع أدوار الأصول الشعاراتية.

## معايير القبول

تُقبل المرحلة فقط إذا وُجد تقرير أصول يميز بين المرئي والمعماري والبياني، وتقرير JSON يوضح البنية والتكرارات والحقول غير المتجانسة، وسجل ألوان أولي مرتبط بالمرجع، وسجل خط بأوزانه، وسجل شعار/أيقونة، وملاحظات Known Issues. لا تُعد هذه المخرجات Design System نهائيًا ولا Schema إنتاجيًا.

## بوابة المرحلة

تُطبق البوابات: `PLAN → IMPLEMENT → RUN → VERIFY → TEST → VISUAL CHECK → ARCHITECTURE CHECK → FIX → RETEST → EVIDENCE → GIT COMMIT → ACCEPTANCE GATE`. لا ينتقل المشروع إلى Phase 3 قبل اجتيازها.
