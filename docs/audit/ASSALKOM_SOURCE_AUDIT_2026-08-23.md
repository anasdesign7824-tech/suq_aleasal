## تعارض موثق يحتاج عدم اختراع حل

العقد يقول إن عدد الصور 81، بينما فهرس الشاشة يعرّف 81 لقطة شاشة **بالإضافة إلى** 9 مخططات PNG في `diagrams/` مرقمة فهرسيًا 082–090. لا أعتبر المخططات مهام شاشة إضافية ضمن 001–081، لكن سأتعامل معها كأصول بصرية منفصلة بعد حسم/توثيق هذا الفرق في التقرير.

العقد يذكر مشروعًا في `/home/ubuntu/assalkom-ux-final` وبيئة غير معروفة، لكن المشروع المتاح فعليًا هو مستودع Windows في `D:\suq_aleasa` على فرع `audit/launch-fixes-2026-08-20`. لا يوجد `AGENTS.md` في المسارات المفحوصة. البيئة الحالية Flutter Mobile + Local Admin Web، وليست مشروعًا جديدًا غير معروف الإطار.

## المعاينة البصرية الأولى

### 001 — شاشة بدء التطبيق

الصورة أبعادها 1440×2560، وتظهر لقطة هاتف عمودية من الحافة إلى الحافة بخلفية كريمية مزينة بخطوط خلية نحل وزخارف نباتية خفيفة في الحواف. في الوسط شعار عسلكم الذهبي والبني مع قطرة عسل وأوراق، تحته «عسلكم» ثم «من اليمن .. طبيعة أصيلة»، وفاصل عسلي، ثم «جارٍ تجهيز سوق العسل...» ومؤشرات تحميل ثلاثية. لا يوجد إطار هاتف خارجي.

### نتيجة baseline للمهمة 001 قبل الضبط النهائي

تم تشغيل اختبار `task001_startup_test.dart` على viewport منطقي 360×640 مشتق من المرجع 1440×2560 بنسبة DPR 4. انتقال البوابة الوظيفي نجح، لكن المقارنة الذهبية بقيت فاشلة بنسبة اختلاف 100% في أول baseline. بعد تسجيل عائلة خط اختبار مستقلة أصبح النص العربي مقروءًا في actual، بينما بقي الفرق البصري بسبب عدم ظهور SVG الشعار في test renderer وبسبب اختلاف نمط الخلفية/الموضع عن المرجع. هذه فجوة golden/asset rendering وليست سببًا لتغيير قاعدة البيانات أو API؛ يجب حل عرض الشعار في harness ثم إعادة المقارنة مع المرجع الأصلي المصغر. أظهر PNG المشتق خلفية سوداء، وأظهرت محاولة إزالة الخلفية آثارًا/أشرطة غير موجودة في المرجع؛ لذلك لا يُعتمد هذا المشتق كأصل نهائي، ويجب إبقاء الأصل المصدر وعدم اختلاق معالجة رسومية غير مطابقة.

### 002 — خطأ بدء التشغيل

الصورة أبعادها 1440×3120، وتظهر شاشة تطبيق كاملة دون إطار جهاز. يوجد شريط علوي بعنوان «خطأ بدء التشغيل» وهوية عسلكم، ثم شريط حالة صغير، ثم بطاقة خطأ كريمية تحتوي العنوان «خطأ بدء التشغيل»، شرحًا، شريطًا عسليًا يحمل «عسلكم»، وسومًا للإجراءات/الأسباب، وزرين سفليين «حفظ» و«إلغاء» كما يظهران في الأصل. هذه الصورة يجب أن تُعامل كهدف بصري، مع تسجيل أي تعارض بينها وبين شرح 002 بدل اختراع سلوك.

## قرار العمل الحالي

مرحلة التنفيذ البرمجي لم تبدأ. الخطوة التالية هي استكمال معاينة كل PNG بحسب الترقيم، وحفظ ملاحظات بصرية دورية، ثم إنشاء جرد مطابقة 001–081 مع المسارات والمكونات والخدمات الحالية. بعد ذلك فقط يمكن عرض قائمة الملفات المتأثرة قبل أي تعديل.

## المعاينة البصرية 005–006

### 005 — إنشاء وتأكيد كلمة المرور

الصورة 1440×3120. تظهر لقطة ذات تخطيط علوي شبيه بلوحة واجهة، مع عنوان «إنشاء وتأكيد كلمة المرور»، بطاقة عسليّة تحمل «عسلكم»، وسوم/مؤشرات للحقول، وزرين «حفظ» و«إلغاء»، ثم مساحة فارغة كبيرة. هذا يختلف بصريًا عن شرح المهمة الذي يصف شاشة هاتف كاملة وحقلي كلمة المرور؛ يجب تنفيذ الصورة والشرح كمرجعين متلازمين وتسجيل الفجوة بدل تخمين إعادة رسم.

### نتيجة تنفيذ TASK 005
نُفذ وضع التسجيل داخل `AuthScreen` دون تغيير عقد المستودع: الاسم والبريد وكلمة المرور وتأكيدها، ومؤشر بصري بثلاث حالات «ضعيفة/متوسطة/قوية»، مع بقاء `_passwordIsStrong` حاجزًا صارمًا قبل `register(name, email, password)`. بقي مسار الحساب الموجود passwordless عبر `requestEmailOtp`، وتحقق اختبار Demo من نجاح التسجيل وتحديث الجلسة. الاختبارات الوظيفية الثلاثة نجحت، بينما فشل golden المصغر 360×780 بنسبة 100% (`280800px`) لأن PNG المصدر لوحة واسعة متعارضة مع شرح شاشة الهاتف؛ لم يُعتمد baseline مصطنع ولم يُغيّر DB/API/RLS/الصلاحيات.

### 006 — الغلاف العام وشريط التنقل السفلي

## جرد معمق للمشروع الحالي

### نقطة الدخول والتوجيه

`main.dart` يقرأ `AssalRuntimeConfig`. في Demo يشغل `AssalApp`، وفي Production يهيئ Supabase ثم ينشئ `ProductionRepository` و`SupabaseAuthGateway` و`SupabaseRealtimeSync`. `AssalApp` يضع Directionality عامة RTL وثيم عسلكم، ويعرض `AssalStartupErrorScreen` عند غياب الإعداد أو فشل التهيئة.

`AssalHomeShell` يبني خمس وجهات داخل `IndexedStack`: اكتشف، المتاجر، التصنيفات، المراسلات، حسابي. على الهاتف يستخدم `NavigationBar`، وعلى العرض الواسع `NavigationRail`. التفاصيل تفتح عبر `MaterialPageRoute`، وليس هناك router مركزي منفصل في Flutter.

### الخدمات والعقود

`AssalRepository` يحتوي عقود القراءة والكتابة للمناطق والتصنيفات والبنرات والمتاجر والمنتجات والمفضلات والمتابعات والتفاعل والتعليقات والتقييمات والطلبات والردود والإشعارات والمحادثات والمصادقة ومساحة التاجر وصور المتجر والمنتج والملف والتوثيق والخطط والحوالات وطلبات التصميم وتسجيل الخروج. بوابة Production تدعم `select`, `insert`, `update`, `delete`, `upsert`, `rpc` ورفع الصور العامة والخاصة.

### مكونات Flutter المشتركة

`assal_widgets.dart` يضم شعار عسلكم، شريط التطبيق، مؤشر التحميل الزجاجي، حالات البيانات والفراغ والخطأ، بطاقة الرسائل، عناوين الأقسام، شارات Premium والدور، بلاطات الأفعال، بطاقات الإشعارات، بطاقات المنتج والمتجر ورأس المتجر والملف وعناصر رفع الصور. حزمة `assal_tokens.dart` تعرف ألوان عسلكم والبني والكريمي والذهبي والأخضر، مسافات 4–64، أنصاف أقطار 8–999، وخط IBM Plex Sans Arabic.

### فروق بنيوية قبل التنفيذ

المحفوظات والمتابعات موجودتان حاليًا داخل `FavoritesScreen` بثلاثة تبويبات، بينما الأصول 029 و030 تفصلهما بصريًا. مسارات المصادقة وOTP وكلمة المرور مجمعة في `AuthScreen` رغم فصلها بصريًا في الأصول 003–005. فتح المتجر للتاجر يبدأ داخل `customer_account.dart` ثم ينتقل إلى `MerchantDashboard`؛ لا توجد وجهة router مستقلة.

مساحة التاجر الحالية تتكون من أربعة تبويبات: نظرة عامة، الكتالوج، الطلبات، إدارة. قسم الإدارة الداخلي يحوي المسودات والمراجعة والإحصاءات والتعليقات. محرر المتجر موجود في نفس ملف `merchant_dashboard.dart`. محرر المنتج منفصل في `merchant_product_editor.dart`، وتفاصيل المنتج والمتجر والطلب والمراسلة موجودة في وحدات العميل مع إعادة استخدامها للتاجر.

### لوحة الإدارة الحالية

`App.tsx` يربط `ErrorBoundary` و`AdminAuthGate` و`Toaster` ثم مسار `/` لصفحة `Home` ومسار `/landing` و`NotFound`. عمليًا، صفحات الإدارة الـ15 ليست ملفات routes مستقلة؛ `Home.tsx` يختار `ViewKey` داخليًا ويعرض الوحدات. لذلك الأصول 048–067 تتطلب إعادة توزيع بصري داخل shell واحد، لا إنشاء API جديدًا.

`Home.tsx` يعرّف مجموعات التشغيل، دورة التاجر، المحتوى والمرجع، الحوكمة، الحسابات والتحليل. ويستخدم `AdminOperations`, `AdminGovernance`, `AdminCreationPanel`, `ProductCreationPanel`, `ProductEditPanel`, `AdminPeople`, `AdminMerchantApplications`, `AdminStoreVerification`, و`AdminPlansPanel`. API الإدارة موثق في `client/src/lib/admin-api.ts`، وكل طلب يمر بمهلة 30 ثانية ومعالجة عربية لأخطاء الشبكة والاتصال.

### قيود Git

الرأس الحالي قبل أي تعديل هو `c546db0`. حالة Git تحتوي 317 ملفًا غير متتبع قديمًا، ولا يوجد تعديل tracked في آخر فحص. لن يتم staging لأي ملف قديم؛ ستُضاف ملفات الجولة الحالية فقط بعد إنهاء الجرد والموافقة الداخلية على قائمة الملفات المتأثرة.
