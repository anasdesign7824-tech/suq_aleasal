# ADR-0001 — Foundation, Naming, and Data Boundaries

## الحالة

Accepted for Phase 1.

## القرار

يُبنى المشروع من الصفر في مستودع `Souq Al Assal / سوق العسل`. الاسم التجاري الظاهر للمستخدم هو **عسلكم**. يتكون الحل من تطبيق Flutter/Dart، ولوحة Admin Web محلية، وصفحة Landing Web عامة للنشر لاحقًا على Cloudflare.

يُعتمد Demo-First Architecture وRepository Abstraction. Supabase هو مصدر الإنتاج الرسمي للبيانات والمصادقة والتخزين، لكنه لا يفرض تشغيل Demo Mode ولا يقود UX أو Domain Model أو User Journey قبل استقرار عقود Demo. يستخدم Flutter عقود Dart، وتستخدم مشاريع Web عقود TypeScript عند الحاجة، مع التطابق الدلالي بين العقود.

## السبب

هذا القرار يحافظ على الثوابت التنفيذية: Greenfield، العربية وRTL، فصل الطبقات، قابلية تبديل مصادر البيانات، وعدم جعل البنية الإنتاجية شرطًا لعرض المنتج وتجربته في التطوير الأولي.

## آثار القرار

سيكون تطبيق الجوال قادرًا على العمل محليًا ببيانات Demo، وستتبع كل Feature بوابات اكتمال تشمل السلوك والحالات والاختبارات والأدلة، وليس مجرد وجود ملفات أو نجاح build. أي تغيير في التقنية أو الهوية أو الحدود المعمارية يحتاج تصعيدًا وقرارًا صريحًا.

## خارج النطاق في Phase 1

لا تُنفذ في هذه المرحلة جداول Supabase أو migrations أو RLS أو APIs أو شاشات المنتج أو تسجيل الدخول أو التكامل الفعلي أو النشر العام. تُثبت حدودها ووثائقها فقط.
